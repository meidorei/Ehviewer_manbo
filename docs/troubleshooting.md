# 常见问题与已知限制

[文档索引](README.md) · [使用指南](usage.md) · [开发与构建](build.md)

## 新加追更为什么是 0？

新条目先建立零基线，后台细化后只统计之后的新增，不把已有全部内容算作更新。先查看任务是否成功，以及使用的是全局扫描还是逐项检查。旧 README 中“第一次扫描不显示、第二次才显示”的问题尚缺可复现结论，不能直接认定当前已修复或必然发生。

## 为什么一直显示 20+？

它可能表示真实数量超过显示上限，也可能表示只能确定数量下界。书签保存全部未读 GID，追更保留 21 条；继续扫描并不保证把标签第一页未覆盖的下界变成精确值。打开书签的清理规则见[使用指南](usage.md)。

## 自动降级是否意味着标签写错？

不一定。语法不能本地匹配、单项边界早于共享游标、全局页数不足都会触发降级。书签检查报告只列预先可确定的查询降级；任务详情中的降级还包含运行时原因。

普通搜索的多词标签应加引号，例如 `artist:"example artist"`。使用完整命名空间，避免把 `f:`、`m:` 当作已支持的本地匹配别名。

## 书签显示 language conflict 或 unsupported mode

前者表示明确指定了非中文正向语言，后者表示搜索模式不支持更新。这些项目不会发送更新请求。查看原始查询和模式后再决定是否修改；修改查询会重建基线。

## 分割线没出现或位置没有立即变化

追更和书签当前页面显示进入前的旧边界；新边界通常下次进入才生效。若边界位于后续页面，需继续加载。首页则必须手动确认重置，不随刷新自动移动。

服务器 Watched 保留旧聚合边界代码，但当前入口不能保证为新安装建立边界。不要用首页或本地追更的行为推断服务器订阅页。

## 暂停后为什么重新扫？重启后为什么没有自动更新？

全局扫描恢复时重新从第一页开始，避免使用不完整内存结果。进程恢复会把遗留运行状态改成暂停，把基线改回待处理；状态恢复不等于自动重新启动服务。已完整提交的项目会保留。

## 阅读队列会删除漫画吗？

默认不会。只有开启自动删除，才会按容量淘汰旧项目并永久删除本地下载目录。默认容量 20 部，可设 1–100 部。仅移出队列与删除下载不同，确认操作前留意按钮含义。

## IGNEOUS 刷新失败或 EX 无法访问

记录当前站点、代理是否开启、任务错误及返回状态。刷新沿用应用网络配置，并先清除旧 IGNEOUS；空值和 `mystery` 都算失败。旧记录中的代理获取失败尚未得到本次网络实测验证，不能承诺某个节点或开关组合必然有效。

JM 文字、封面及网页回退使用不同请求，封面失败不代表文字结果无效；外部服务变化也可能导致只返回部分资料。

## 安装提示签名不一致

`INSTALL_FAILED_UPDATE_INCOMPATIBLE` 表示需要核对已有 Debug 包与 APK 签名。检查固定主机 keystore、`USERPROFILE` 和 APK 证书，按[构建文档](build.md)处理；不要卸载旧包绕过签名检查，以免丢失数据。

源码当前为 `154 / 154`，APK 输出与手机安装结果见[变更记录](../说明.md)。文档更新不会改变手机中的已安装应用。

## 测试为什么在执行主体前失败？

JUnit 使用 4.13.2，Robolectric 使用 4.2.1。Java 21 和 targetSdk 30 下旧 Robolectric 可能出现模块反射或 `targetSdkVersion=30 > maxSdkVersion=28` 初始化错误。应从当次测试 XML 区分初始化错误与实际断言失败，不能把这些测试算作通过。

2026-09-09 的 tests=211、failures=8、errors=0、skipped=2 仅为历史结果。本次文档整理未运行应用测试。

## 反馈问题时提供什么？

提供应用包名、versionName/versionCode、Android 版本、操作入口和步骤、预期与实际表现。更新问题补充扫描方式、站点、任务阶段、错误文字和是否切换过账号；安装问题补充完整安装错误。不要在日志中公开身份 Cookie。
