# 扫描与未读机制

[文档索引](README.md) · [使用指南](usage.md) · [架构与数据](architecture.md)

本文描述当前源码行为。旧文档中的“所有来源最多 21 条”“逐书签只检查第一页”已不适用。

## 边界、时间和计数

`FeedBoundary` 保存发布时间的 Unix 秒和该秒已见过的 GID 集合。发布时间更晚，或同秒但 GID 不在集合中，才视为新增。同秒结果必须完整处理，不能遇到一个已知 GID 就停止扫描。

| 状态 | 含义 |
| --- | --- |
| `*_SYNC` checkpoint | 对应查询已检查的内容边界 |
| `*_OPEN` checkpoint | 用户成功打开列表时记录的阅读边界 |
| `LOCAL_GLOBAL_CURSOR` | 同一账号、站点、任务类型与查询签名共享的扫描停止位置 |
| `CHECKED_AT` / `LAST_CHECKED_AT` | 实际完成检查的时间 |
| `UPDATED_AT` | 数据库记录写入时间 |

`globalTop` 是本轮中文全局列表顶部的发布时间及同秒 GID，不是运行任务时的系统时间。12:00 检查而最新内容发布于 11:58 时，内容边界应是 11:58。

`LOCAL_UNREAD_GALLERY` 以来源类型、来源键和 GID 去重。书签来源不限条数；追更保留 21 条。显示层的 `20+` 既可能表示超过显示上限，也可能表示扫描未完整覆盖的数量下界。

## 全局与逐项扫描

全局扫描强制中文，从最新页向后读，越过共享游标的完整时间组后停止。页数范围 1–300，默认 30；来源首次建立时只设零基线，旧版本缺少共享游标时可从已有单项最旧边界开始迁移。

| 路径 | 完成后的边界 |
| --- | --- |
| 追更逐标签 | 读取第一页；非空时推进至标签顶部，无法覆盖旧边界则标记下界；空结果只更新检查时间 |
| 追更全局完整覆盖 | 分别计算匹配 GID，各项推进至本轮 `globalTop`，包括没有匹配结果的标签 |
| 追更全局超过页数上限 | 降级逐标签第一页，沿用标签边界；降级队列全部成功后提交共享游标 |
| 普通逐书签、单书签 | 连续翻页到旧 checkpoint 或末尾，成功后推进至书签顶部；空结果不推进内容边界 |
| 书签全局精确匹配 | 完整覆盖后使用各自匹配结果，边界推进到本轮 `globalTop` |
| 书签旧边界桥接或页数降级 | 连续分页补算；取得有效同步顶部时推进至该顶部，否则沿用书签自己的顶部 |
| 书签复杂查询降级 | 连续分页检查，保留独立查询边界 |

任务内部的 `FIRST_PAGE` 是保留的方法名，不代表当前书签只扫描一页。实际入口 `checkBookmark()` 使用 `BookmarkScanAccumulator` 连续处理分页。

自动降级数量包含语法不支持本地匹配、旧 checkpoint 需要桥接、以及共享游标未被页数上限覆盖三类原因。它本身不是失败。

## 标签与查询匹配

完整命名空间为：

```text
artist group parody character female male misc language
cosplayer mixed other reclass
```

追更只接受标准 `namespace:value`，统一首尾空格、连续空白和大小写。完整多词值不会拆词；不要给追更标签加末尾 `$`，也不要使用命名空间简写。

书签的本地精确匹配支持标准标签、正负标签的 AND 组合、正向 uploader、分类、最低评分及页数范围。普通搜索的多词标签须带引号；标签模式按整体处理。标准标签末尾 `$` 可有可无。

`l:` 和 `lang:` 可映射为 `language:`；其他简写如 `f:`、`m:` 未被识别时降级。全文关键词、标签混全文、OR、模糊表达式、通配符和负向 uploader 等无法由列表元数据精确重现的查询也降级。

这是匹配能力判断；`BookmarkUpdatePolicy` 还会先验证更新资格。特殊模式和非中文正向语言条件分别返回 `unsupported mode`、`language conflict`，不发更新请求。

书签签名包含 mode、分类、关键词、高级搜索、评分、页数及中文策略。名称不参与签名；条件变化会清理旧状态和边界并重建基线。

## 请求与提交完整性

更新使用 `EhEngine.getGalleryListForUpdate()`，不套用普通浏览的本地过滤器。必要的标签、发布时间、分类、上传者、页数或评分不完整时通过 gdata 补齐，每批最多 25 项。

搜索请求间隔在每次列表请求前执行，不额外限制 gdata、图片或普通浏览。任务创建时保存间隔快照。

书签扫描先在内存收集新增 GID，完整结束后由 `commitBookmarkScan()` 在事务中提交未读和 checkpoint。重复分页 URL、无效时间戳、暂停、停止和网络失败都不能提交该项半截结果。全局游标也只在对应流程成功后推进。

任务不是覆盖所有项目的单个数据库事务：前面完整成功的项目已经提交，后续项目失败不会回滚它们。应区分“单项提交完整性”和“整批任务全部成功”。

## 暂停、来源切换与恢复

`LocalUpdateService` 通过进程内活动标记限制单个任务，状态保存在 `LOCAL_REFRESH_JOB`；阶段包括准备、全局扫描、追更队列、书签队列和基线。

暂停或停止会取消当前网络请求并中断工作线程。逐项任务从持久化索引恢复，全局阶段重新扫描第一页，基线从未完成队列继续。进程重启把遗留运行状态改为暂停，基线运行项改为待处理；这不等于自动启动服务。

可用 IGNEOUS 优先 EX，否则使用 E；EX 请求失败会尝试 E。全局阶段切换 host 后清空本轮内存结果并按新来源重新开始。同步边界按账号与 host 区分，具体数据范围见[架构与数据](architecture.md)。

## 打开列表与分割线

进入追更或书签时读取旧打开边界，同时记录未读批次的 rowid 上限。成功打开后保存新的非空页面顶部，清除进入前批次；当前画面仍使用旧边界，下次进入才使用新边界。书签合法空结果也清理该批次，但不写入空顶部。

书签清理还会删除其他书签中相同 GID 的未读关系。符合 `BookmarkUnreadClearPolicy` 条件的其他书签清零时，打开边界可推进至其最近成功更新边界；不能用稍后打开时的实时顶部代替，不能把部分减少或下界状态强行当成精确清零。

首页分割线使用独立手动机制，只有用户确认重置才改变。服务器 Watched 保留旧聚合边界实现，不应据此承诺新安装可自动建立该边界。
