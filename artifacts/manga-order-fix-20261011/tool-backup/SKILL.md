# EhViewer 漫画库整理

由当前智能体读取书库标题，判断哪些漫画属于同一系列，再按阅读顺序整理。直接把事情做完，不建立多轮审核项目。

## 怎么识别同一系列

标题写法不同不代表作品不同。必须考虑以下情况，不能只靠字符串相似度、相同汉字或英文关键词判断：

- **中文译名**：同一日文作品可能有简体、繁体、直译、意译和不同汉化组采用的名字。先理解标题含义，再判断是不是同一作品。中文译名不必逐字对应原文。
- **日文原名**：汉字、平假名、片假名的不同写法，以及全角半角、标点、空格、长音符号差异，可能仍指向同一题名。利用 titleJpn 与主标题互相核对；两者明显冲突时保留疑问，不盲信某一个字段。
- **英文译名**：英文可能是日文标题的翻译或发行别名。不能因为没有共同字符就拆成不同系列；也不能因为英文意思接近就把不同作品合并。
- **日语罗马音**：这是日文读音的拉丁字母转写，不是英文译名。例如日文「青い庭」可写为 `Aoi Niwa`，与中文「蓝色庭院」、英文 `Blue Garden` 可能指同一作品。这个例子仅说明判断方法，实际归属仍需核对作者及作品信息。
- **罗马音的写法变化**：长音可能写成 `ou`、`oo`、`ō` 或省略；助词可能写成 `o/wo`、`e/he`；还有分词、连写、大小写和标点差异。将这些作为候选线索，结合原日文判断，不把机械替换当成确认。
- **作者与社团别名**：作者也可能用汉字、假名、中文译名或罗马音署名。结合社团、作品题名及其他已知条目确认作者身份；汉化组、语言标签、展会名不能当成作者。同社团也可能有不同作者。
- **续篇和省略题名**：第 2、3 篇可能省略长副标题，或只写简称、角色名、前篇/后篇。结合前作、作者、主体题名和篇章标记判断。番外、后日谈、总集篇及重制版也应检查是否属于已存在系列。
- **附加标签**：汉化组、展会编号、语言、Digital、Uncensored 等通常不是作品名的一部分。识别时可忽略这些干扰，但展示和保存时保留原始标题。

确认作者/社团身份及作品关系相符后，即使中文、日文、英文和罗马音完全不像，也应归入同一系列，并用一个清楚的系列名展示。需要消歧时在系列名后加作者。翻译版本保留各自 GID，放在同一篇章附近，不删掉任何版本。

相同作者、相同题材、相同人物或同一个原作 IP 都不自动等于同一系列。不同故事或支线需要区分；同名但作者不同的作品通常分开。证据不足时独立保留，并简短说明可能关联到哪里。确有必要时查公开作品页，核实后记录来源；不把整个书库上传联网，也不为每条漫画固定做搜索。

## 怎么排序

- 系列整体尽量保持原来的位置；把散落成员收拢到该系列最早出现的位置。
- 系列内默认从较早卷章开始，同章不同翻译相邻。真正的故事分支分开排列。
- 正篇、番外、合集、重制版分别标明；合集保留为一本，不展开或删除其覆盖的单篇。
- 原题明确的第 0 章可以保留。未编号不等于第 1 章；上下篇、前后篇有明确对应时才换算顺序。
- 发布日期、平台 ID、版本号、Season、合集数量不能随意当章号。不同编号体系无法比较时，把位置留空，保持原相对顺序。

## 怎么执行

1. 获取目标应用的数据库副本或已有标题清单。已有导出和判断可以直接续用，不重做已完成的工作。
2. 当前智能体分批读取标题，边理解边归组；批量大小按标题长度和上下文调整。每本都要看过，但不要求重复扫描全库。程序可以帮助索引作者或检索近似标题，系列关系由智能体判断。
3. 只回看具体疑点与相关成员。已经明确的结果直接沿用，没有新证据就保留独立，不为消灭所有疑问不断复查。
4. 写简短的系列清单，生成完整顺序和离线预览。用户可以搜索、调整归组或顺序、保存进度，以及一次确认整个结果。无需逐本打勾才能完成。
5. 用户确认要将该结果写回时，先生成数据库备份和排序副本，校验后再替换指定手机应用的数据库。

具体文件格式和命令见 [工具用法](references/tools.md)。预览页使用 [固定模板](assets/review.html)，样式调整修改该模板并重新生成；生成的单文件网页无需联网。使用一个智能体即可；只有用户明确要求时才委派。没有固定审核轮次、模式切换、discovery 注释、覆盖证明、审计摘要链或逐文件登记任务。不要重新引入这些流程。

## 大书库与聊天响应

检查、调试或修改本 skill 时只处理技能本身，不启动漫画整理或手机操作。

- 读取标题使用工具的 `titles` 分页命令，默认每次最多 40 条、6,000 字符，按 `nextOffset` 接着读。完整 catalog、候选清单和网页保存在文件中，不能用 `Get-Content -Raw`、无上限循环输出或一次浏览器快照把整库塞入聊天。工具层的输出截断不能代替源头限量；大量原始输出仍可能留在聊天记录中。
- 已有归组只在确认对应条目确实读过时续用；用新旧 catalog 比较新增和改题，再分页读取这些条目及相关成员。仅有旧预览不等于全库已读。首次整理仍需读完每本，但每批把归组写入 `groups.json`，在一个简短进度文件中保存输入路径、当前筛选条件、下一偏移和已读范围；中断后从文件续接，不重新加载全库。
- 作者、题名检索先建立索引或按具体关键词缩小候选范围，再做相似度比较。避免每个候选与全库逐对比较；宽泛关键词命中很多时，先报数量再分页，不能打印所有关联标题。
- 长命令异步执行，单次等待不超过 60 秒，约每分钟说明已完成范围与下一步。用户说停止或询问状态时先响应；停止时保存当前批进度。任务应持续推进，分批不要求用户反复确认，也不能把未读条目说成已完成。
- 完整结果用文件链接交付。预览页面可在本地打开，检查时优先读取摘要或局部元素，避免抓取包含全部标题的页面快照。

## 只保留必要的数据保护

保留所有 GID、原标题和下载文件，不删除疑似重复项。手机操作只针对用户指定的应用，遵守工作区的包名限制，先检查当次设备连接。数据库使用一致性副本；不能为了导出而删除 WAL/journal 或强行使用不完整文件。

排序只修改 DOWNLOADS.TIME。写回前核对书库没有新增、删除或改题，备份原库；写入副本后校验 SQLite 完整性、实际顺序及其他表/字段未改变。手机替换后重新读取核对，确认可启动。异常就停止写回并保留备份。

交付时说明整理数量、归组结果、仍不确定的关系，以及实际是否写回手机。不要把程序检查通过说成所有作品关系都已得到人工证明。
