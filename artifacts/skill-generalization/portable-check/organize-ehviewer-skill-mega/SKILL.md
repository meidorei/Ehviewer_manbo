# EhViewer 漫画系列整理

把任意兼容的 EhViewer 标题清单整理成可检查、可修正的系列与顺序。保留原始 GID 和题名；程序只产生候选与排序，系列语义由当前主模型判断。

## 入口与适用范围

- 保留当前 skill 名称和目录。统一入口为 `python scripts/organize.py --help`；首次使用子命令先运行该命令的 `--help`。
- 接受本地 `eh.db`、标准标题 JSON 清单或可选 ADB 导入；本地整理不要求连接手机。核心只依赖 Python 3.10+ 标准库。
- 不支持普通漫画文件夹重命名或压缩包重排。不假定所有 EhViewer 分支使用同一 schema；不兼容数据库只生成可安全读取的清单或说明缺失字段。
- 只处理本次明确指定的数据和应用包。ADB 必须提供路径、设备和包名；遵守工作区对正式包的限制，不自行选择其他应用，不使用 root。

## 默认分类与排序

- 作者相同、题名相似或机器生成的别名都只能成为候选依据，不能自动合并作品。
- 不确定归属的条目独立保留，附候选关系、理由和待审标记。不要删除重复翻译、章节合集或疑似重复下载。
- 主模型可按需查公开作品页面核实疑难关系，记录来源与支持的结论；搜索摘要不构成证据。无法访问或证据不足时保留待审。
- 每个系列保持最早原始成员的锚点。系列内依次展示正篇、番外、合集、重制版、其他；故事分支分别展示。
- 组内默认按可靠卷章位置升序，从第一章开始；可切换降序。同位置的翻译版本相邻并保留源顺序。未知位置位于对应组末尾，不把未知等同第 0 章。
- 分类置信度与顺序置信度分开记录。没有可比较的位置依据时将 `orderReliable` 设为 `false`，不要靠编号猜测阅读顺序。

## 完整流程

1. 建立本次独立输出目录，默认位于 Android 工程之外；不覆盖已有文件。SQLite 用一致性备份导入，JSON 清单统一为 v3。已有 v2 结果必须显式迁移。
2. 全库 discovery 默认每批 75 条，只提供 GID、原位置、原题、日文题；每条恰好一个简短注释，验证完整覆盖与双指纹。
3. 生成有边证据的候选、完整作者桶、碰撞审核和未决索引。大集合按最多 75 条分批，跨批关系必须保留。
4. 当前主模型依次完成候选、作者、未决、全局四轮审核。每轮使用最新决策重新生成候选／未决索引；记录输入摘要、全部 GID 覆盖及无冲突结果。主模型语义判断不委派给子代理，除非用户明确要求。
5. `build` 验证完整审核链并生成模型顺序。`review` 生成自包含离线页面，所有题名与 GID 均存在于静态 HTML。
6. 将审核页交给用户。用户可以合并、拆分、修改归属、编辑位置、移动系列／单本、撤销、保存和恢复进度；确认保留所有待审条目的现状后导出确认 JSON。
7. 停在审核结果阶段，直到用户返回或明确确认导出的完整结果。不得以脚本测试或模型自评替代真实书库的人类确认。
8. 有写回授权时，用原模型文件重放校验人工操作，再对新鲜一致性快照核对 GID 与标题元数据指纹。`apply` 只生成备份、排序副本和报告。
9. 设备替换前后按工作流复验；保留电脑和手机备份。任何指纹、权限、数据、顺序、完整性或哈希异常都停止。

## 数据与输出保护

- 不把数据库二进制、路径、令牌、Cookie、账号或下载目录作为模型输入。联网时只发送当前疑难作品所需的公开题名与作者信息，不批量上传书库。
- 写回只有 `DOWNLOADS.TIME` 可以变化；检查全部表数据与 schema。首条使用当前毫秒时间，后续每条递减一秒，实际 `TIME DESC` 必须完全等于确认顺序。
- 清单中的 `writebackSupported` 仅说明兼容性，不代表授权。人工确认、输入绑定和数据库验证仍必需。
- 新增或删除 GID、修改标题后必须重新导入；不能给旧确认结果换个指纹继续使用。
- 每个生成文件立即登记到 `run-manifest.json`：中间 discovery、审核输入、未决索引、候选和页面为 temporary；原快照、模型基线、确认结果、报告及备份为 preserve。模型基线是人工操作重放的依赖，不能清理。
- 不自动清理。只有用户明确要求，且两个绑定相同结果的启动前／启动后数据库报告通过时，才预览并确认清理。

## 交付说明

报告条目数、系列数、待审数、双指纹、模型／确认文件摘要、备份与副本位置、实际通过的验证阶段及限制。测试样本的召回率不是实际书库的分类准确率；没有独立人工标注数据时不声称已证明真实准确率。
